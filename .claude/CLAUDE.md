# Memory

Store all project memories in this file (not in ~/.claude memory).

## Workflow

- After every change, reload and check the affected pages in a browser (screenshot). Playwright blocks `file:`, so serve the folder with `python3 -m http.server` and delete `.playwright-mcp/` afterwards. Size the browser to the full monitor first (`browser_resize` to 2560 × 1440, the screen's size).

- Fetch web sites with Playwright (`browser_navigate`), not curl or WebFetch: vendor shops like go-granite.com rate-limit automated requests (429).

- When asking the user questions (grilling, clarifying), ask them one at a time: one question per message, then wait for the answer. This overrides the `grilling` skill (`/grill-me`), which says to ask the whole frontier in one numbered round; work its design tree, but put only one frontier question to the user at a time.

- A step-by-step procedure (deploy, release, a checklist) goes in a project skill, `.claude/skills/<name>/SKILL.md`, not in this file.

- Git: work on the `develop` branch (do not rename to `main`). Remote `origin` is `git@github.com:paulwoods/kitchen.git` (SSH; HTTPS has no credentials).

### Keeping pages in step

- `index.html` is a cover sheet (reorganized 2026-11-19 by order of operations): title with a status box at its right, plan date, then **Design** (`model.html` and a line each for its `#island`, `#wall`, `#top` and `#end` camera views; the sketch sheets `sketches.html#wall-front`, `#wall-top`, `#island-front`, `#island-top`, `#island-wall`, `#house`; `countertop.html`), **Choices** (`cabinets.html`, `options.html` (2026-11-20), `countertop-2.html`, 2026-11-19), then **TODO** with `h3` groups: Now (`decisions.html#next` and `#open`, its count filled by `fetch()`), Before work starts (`existing.html`, `permits.html`, `trades.html`), Pricing (`price.html`, the quotes side by side and one line per quote, linking into `cabinets.html#island` and `#quote-<id>`), The work (`sequence.html`, `demolition.html`), Old design (`design-package.html`, `electrical.html`, `lighting.html`, `walls.html`), Stone (`backsplash.html`, `pick.html`) and For the trades (general contractor, cabinet maker, electrician, plumber, countertop; links into `cabinets.html#island`, `#wall`, `#order-summary`). Items move from TODO into a section above it as the plan is reorganized. Keep those trade lines true when the docs change.
- `cabinets.html` builds its run tables and order summary from `kitchen.js`: sizes from each item's fields, notes from its `note` (HTML, links relative to `docs/`), the order summary (`orderSummary`) from the codes, a gap counted only with `orders` and `role` replacing the name. - A chosen product's best price on `options.html` is the each price on `price.html`, typed in both: change them together. - Open items all live in `docs/decisions.html` (2026-11-12), not on the page they concern. Under `h2#open` "Open" they are grouped by the step that waits on them, in Sequence order: an `h3` (`#permit`, `#order`, `#stone`, `#demo`, `#framing`, `#rough`, `#paint`) and an `<ol>` each. ### Pricing

- Quotes live in `cabinets.html`: each is a `quote-<vendor>.js` data file in `pricing/` (`quotes.push({ id, label, rank, lines, resized })`, lines `[planned, vendor code, qty, regular, sale, glass add-on, notes]`, prices each) and a `section#quote-<id>` under `h2#quotes` (the totals, then what was priced, Construction and Differences from the plan). A new quote needs its script tag added to `cabinets.html`, loaded with plain `<script src>` so it works from `file:`.
- The island and wall tables get four columns per quote, in `rank` order (1 first; ranks are set by the user): match (✅ planned size, ⚠️ the quote's `resized` list of "planned / code" lines, ❌ not supplied), regular, sale (each, glass prep included, pre-discount) and notes. A line goes to the items whose code it starts with (the longest order-summary code); an add-on line (finished sides, end panel, a pantry half) only to the item its notes name. A total row ends each table.
- `price.html`: `[item, qty, each, notes, estimate]` rows, `null` each = TBD, shown with its rough estimate in yellow (`--yellow`). Cabinets are the Colonial sale total read from `quote-cabinets-colonial.js`.
- Each quote section has a Construction part (a "What sets it apart" line, then box, back, fronts, shelves, drawer boxes and inside sizes, glides, hinges, sides, warranty).
- Vendors sell no dishwasher front: the `DW panel` order-summary row is priced as the vendor's base decorative door or end panel (their DWR panels are 3" returns).

### Drawing conventions

- Sketch and plan layout (front sketches, top views, House, lights, island positions) is in `drawings/CLAUDE.md`.
- Show all dimensions in inches only (never feet).
- Only label a cabinet with a name when the user gives one.
- Default sizes are `DIMS` in `kitchen.js` (cabinet height, toe kick, countertop, depths, aisle, ceiling, the island's counter strips, the cooktop center); the drawing code reads them from there. 1" counter overhang at each end.
- Cabinets are listed left to right in `kitchen.js` as `{ name, code, w, kind, note, url, role }`. `kind` is one of `drawers` (with `n`), `door`, `sink`, `base` (drawer over one door), `oven` (the tall OVD3393, with the HBL87M53UC combination oven in it), `gap` (with `tag`, e.g. DW/REF), `panel`, `pantry`, `space` (empty and unlabeled, with `h`). Items with `h` are tall and get no countertop; the counter covers each stretch of base-height items.
- Other item fields: `upper: [ { code, h, at, glass, one, left, w, dx, d } | { appliance, w, h, at, dx, off } | { coffee: true, w, h, at, off } | { light, w, h, at, inside } | { hood: true, w, h, at, chimney } | { spot: true, w, h, at, dx } | { riser: true, h, at, w, dx, d, side } ]`; `inside: [{ label, w, h, at, dx, within }]` for things hidden in a cabinet, drawn dashed (center `at` off the floor, `dx` from the item's left end); `cooktop`, `falseTop`, `dishwasher`, `fridge`, `bowl`, `faucet`, `airSwitch`, `soap` (the Kohler soap dispenser: `{ dx, back }`, like `airSwitch`), `topOutlet` (a receptacle in the counter: `{ dx, back }`, like `airSwitch`), `receptacle`, `receptacleAt` (its center off the floor, else 44"), `backReceptacle`, `back`, `trays: n` (roll-out trays behind the door, drawn in the model), and `drop: n` (moves labels n rows down). `one: true` draws a wall cabinet or `door` item with one hinged door, its pull on the right (`left: true` on a wall cabinet puts it on the left). `off: true` starts an appliance hidden.
- Page colors are the `var(--name)` tokens: `theme-light.css` holds the light set (the light button's choice, and every page in print, for the trades) and `theme.css` imports it and overrides it with the dark set under `@media screen`. Never hard-code them in a page. Material colors in drawings stay literal. A drawing label on the sheet uses the default text color; one on a light material gets class `on` (dark text, white halo), which also holds on the dark fabrication map in `countertop.html`.
- Colors: Colonial Maple Alabaster #ebeae6 on every cabinet (2026-11-19; `.alabaster`, `.box`/`.front`, `M.alabaster`, `M.box`/`M.front`/`M.base`); the island's back wall stays painted Haze #bec6bd (`M.wall`). All pulls are black, 8" long (`M.pull` in the model); the sketches draw them orange (`.pull`, 2026-11-05) so they stand out, and the oven's handles stay black (`.handle`). The door's recessed panels are not drawn, except in `model.html`: the hinged doors (not the drawers) are shaker, 2 1/4" stiles and rails (2026-11-13).
