# Memory

Store all project memories in this file (not in ~/.claude memory).

## Workflow

- After every change, reload and check the affected pages in a browser (screenshot). Playwright blocks `file:`, so serve the folder with `python3 -m http.server` and delete `.playwright-mcp/` afterwards.

- Git: work on the `develop` branch (do not rename to `main`). Remote `origin` is `git@github.com:paulwoods/kitchen.git` (SSH; HTTPS has no credentials).

## Kitchen

- Galley kitchen with two sides: **island** and **wall**.
- `index.html` is a cover sheet: plan date, a status box, then Drawings and model (top view, island front, wall front, `model.html`), Documentation (`anomalies.html`, `cabinets.html`, `appliances.html`, `electrical.html`) and For the trades (cabinet maker, electrician, plumber, countertop; links into `cabinets.html#island`, `#wall`, `#order-summary`). Keep those trade lines true when the docs change. `cabinets.html` documents every cabinet, panel and filler per run plus an order summary; update it whenever the sketches change. `anomalies.html` (titled "Issues") lists open inconsistencies between the appliance/electrical docs and the sketches under "Open" (or "None, as of <date>") and dated decisions under "Resolved"; keep it current. Open items go in a `<ul>` right after `h2#open` (a `<p>` when there are none), resolved items in the `<ul>` after `h2#resolved`: `index.html` counts them with `fetch()` and takes the latest date in the page as "Plan as of". Its typed status text is only the fallback when opened from the folder (`file:`), so update it too.
- Each side is a sketch: `sketch-island-front.html` ("Island front"), `sketch-wall-front.html` ("Wall front"). Page headings match their index link and tabs read "Page · Galley Kitchen". Both use `sketch.js`, which draws a front elevation on graph paper (1 square = 6", bold line every 30", measured from the left end of the run and the floor). A ruler on the right marks the toe kick, countertop, shelf tops, tops of the upper cabinets and the 96" ceiling.
- Every sketch has a tape measure (`tape()` in `sketch.js`, set up by `page()`): drag to measure, snapping to the rect and line edges in the drawing.
- The wall front passes `{ toggles: true }` to `sketch()`: a checkbox per appliance (fridge, oven, microwave, toaster oven, air fryer, coffee maker) plus "all appliances" hides/shows them; hidden shapes don't snap the tape. `off: true` on an appliance starts it hidden (the microwave, toaster oven, air fryer and coffee maker do); a receptacle behind a hidden appliance draws solid.
- `sketch-top.html` is a top view (plan) of the whole galley via `plan(title, island, wall, { riser: true })` in `sketch.js`: island at the top facing down, wall run at the bottom facing up (so it reads right to left), 48" aisle between cabinet fronts, depths measured from the wall. The wall run's right end (Coffee) lines up with the island's left end (spices). The fridge is drawn 28.5" deep (with doors); upper cabinets are dotted (depth from the code, e.g. W362424 = 24", else 12"). Countertop appliances are not drawn. Island counter 25" deep (1" over the 24" cabinets); riser drawn 4.5" thick (assumed); cooktop (31" x 21 1/4") centered on the counter (assumed); sink (33.5" x 19") 2" from the counter front (moved 1" forward, 2026-10-24). Faucet (Kohler K-R30937-BMB) is drawn in both island sketches as `faucet: { h: 22.4375, reach: 9.5, back: 3 }` on the sink item: centered on the SB42, 3" from the riser face (moved 1" back, 2026-10-24).
- `model.html` is a 3D model of the galley (three.js 0.160.0 from jsdelivr, orbit controls; End / Island / Wall / Top views, where Island and Wall hide the other run). It has its own copy of both runs, laid out as in `sketch-top.html`; update it when the sketches change. Countertop appliance depth (14") is assumed; the hood is 23 5/8" deep (Proline sheet). The cooktop is black glass with four zone rings and a front touch strip (layout assumed, as in the top view). The sink is cut into the counter (the counter is built in four pieces around a 31 7/8" x 17 3/8" opening) with an open steel bowl 9 7/8" deep (bottom drawn flat), ledges front and back and the drain on the left; the SB42 is drawn hollow above the bowl so it shows (2026-10-25).
- Every page starts with `<html lang="en">` and a viewport meta. On phones (under 600px) the cabinet and appliance tables stack each row: short fields on one line, notes below. `model.html` sizes its canvas from the viewport (`clientWidth`), not `innerWidth`.
- Show all dimensions in inches only (never feet).
- Cabinets are listed left to right in each html file as `{ name, code, w, kind }`. `kind` is one of `drawers` (with `n`), `door`, `sink`, `base` (drawer over one door), `oven`, `gap` (with `tag`, e.g. DW/REF), `panel`, `pantry`, `filler` (plain base-height strip). Items with `h` are tall (panels, pantry, fridge space) and get no countertop; the counter covers each stretch of base-height items. Add `cooktop: true` to draw a cooktop on the counter.
- Default sizes: cabinets 34.5" tall, 4.5" toe kick, 3 cm (1.25") quartzite countertop (35.75" counter height), 1" counter overhang at each end.
- Only label a cabinet with a name when the user gives one.
