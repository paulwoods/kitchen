# Memory

Store all project memories in this file (not in ~/.claude memory).

## Workflow

- After every change, reload and check the affected pages in a browser (screenshot). Playwright blocks `file:`, so serve the folder with `python3 -m http.server` and delete `.playwright-mcp/` afterwards.

- Git: work on the `develop` branch (do not rename to `main`). Remote `origin` is `git@github.com:paulwoods/kitchen.git` (SSH; HTTPS has no credentials).

## Kitchen

- Folders (2026-10-31): `index.html`, `nav.js`, `kitchen.js` and `favicon.svg` stay at the root; `drawings/` holds the sketches (`sketches.html`: wall front, wall top, island front, island top, each a `section` from `page()`), `sketch.js` and `model.html`; `docs/` the documentation pages; `pricing/` the price page and the quotes' `quote-*.js` data files; `cabinets/` (vendor notes) and `manuals/` (PDFs). Pages in a folder link with relative paths (`../index.html`, `../docs/cabinets.html`) and load `../nav.js`, which builds its links from its own location. File names below are given without their folder.
- Galley kitchen with two sides: **island** and **wall**.
- Where things are recorded: current sizes and the runs in `kitchen.js` (`DIMS`, `RUNS`), the one source; descriptions, models and installation detail in `cabinets.html` (via each item's `note`), `selections.html` and `electrical.html`; decisions and their history in `issues.html`; assumptions in a comment beside the value. Add new detail there, not here.
- A number in a text page that comes from `kitchen.js` is written `<span data-k="counter">25 3/4</span>"` (`<tspan>` inside an SVG): `nav.js` loads `kitchen.js` if needed and replaces the text with the value, as a fraction. `data-k` takes an expression of `DIMS` names (`counter + seat`), so derived numbers follow too. Change the value in `kitchen.js`, never the span text. `issues.html` is a dated log and keeps its numbers as typed.

### Keeping pages in step

- `index.html` is a cover sheet: title with a status box at its right, plan date, then, in up to three columns, Model (`model.html` and a line each for its `#island`, `#wall`, `#top` and `#end` camera views), Sketches (wall front, wall top, island front, island top: `sketches.html#wall-front`, `#wall-top`, `#island-front`, `#island-top`), Documentation (`cabinets.html`, `selections.html`, `countertop.html`, `backsplash.html`, `pick.html`, `lighting.html`, `electrical.html`, `walls.html`, `sequence.html`), Pricing (`price.html`, then the quotes side by side and one line per quote, linking into `cabinets.html#island` and `#quote-<id>`), Issues (`issues.html`) and For the trades (general contractor, cabinet maker, electrician, plumber, countertop; links into `cabinets.html#island`, `#wall`, `#order-summary`). Keep those trade lines true when the docs change.
- `cabinets.html` builds its run tables and order summary from `kitchen.js`: sizes from each item's fields, notes from its `note` (HTML, links relative to `docs/`), the order summary (`orderSummary`) from the codes, a gap counted only with `orders` and `role` replacing the name. Edit the note in `kitchen.js` along with the item.
- `walls.html` gathers the island wall, the room wall and the side wall (sizes, framing, box positions) from the other pages; update it when any of those change.
- `issues.html` lists open inconsistencies between the appliance/electrical docs and the sketches under "Open" (or "None, as of <date>") and dated decisions under "Resolved"; keep it current. Open items go in an `<ol>` right after `h2#open` (a `<p>` when there are none), resolved items in the `<ul>` after `h2#resolved`: `index.html` counts them with `fetch()` and takes the latest date in the page as "Plan as of". Its typed status text is only the fallback when opened from the folder (`file:`), so update it too.
- The runs live only in `kitchen.js` (`RUNS.island`, `RUNS.wall`, a plain script loaded before `sketch.js` or the model's module); all four drawings read it. Each view ignores the fields it doesn't draw, so add a field there once rather than per page.
- Every page starts with `<html lang="en">` and a viewport meta, followed by `<script src="nav.js" defer></script>` and `<link rel="stylesheet" href="theme.css">` (`../` from a folder; `sketches.html` loads `theme-light.css` instead). `nav.js` draws a row of links across the top, the current page in bold. `nav.js` also adds the favicon. Keep its list in step with `index.html`; it goes inside `model.html`'s header so the canvas height still fits. On phones (under 600px) the cabinet and appliance tables stack each row. `model.html` sizes its canvas from the viewport (`clientWidth`), not `innerWidth`.
- Page headings match their index link and tabs read "Page · Galley Kitchen".

### Pricing

- Quotes live in `cabinets.html`: each is a `quote-<vendor>.js` data file in `pricing/` (`quotes.push({ id, label, rank, lines, resized })`, lines `[planned, vendor code, qty, regular, sale, glass add-on, notes]`, prices each) and a `section#quote-<id>` under `h2#quotes` (the totals, then what was priced, Construction and Differences from the plan). A new quote needs its script tag added to `cabinets.html`, loaded with plain `<script src>` so it works from `file:`.
- The island and wall tables get four columns per quote, in `rank` order (1 first; ranks are set by the user): match (✅ planned size, ⚠️ the quote's `resized` list of "planned / code" lines, ❌ not supplied), regular, sale (each, glass prep included, pre-discount) and notes. A line goes to the items whose code it starts with (the longest order-summary code); an add-on line (finished sides, end panel, a pantry half) only to the item its notes name. A total row ends each table.
- `price.html`: `[item, qty, each, notes, estimate]` rows, `null` each = TBD, shown with its rough estimate in yellow (`--yellow`). Cabinets are the Colonial sale total read from `quote-cabinets-colonial.js`.
- Each quote section has a Construction part (a "What sets it apart" line, then box, back, fronts, shelves, drawer boxes and inside sizes, glides, hinges, sides, warranty).
- Vendors sell no dishwasher front: the `DW panel` order-summary row is priced as the vendor's base decorative door or end panel (their DWR panels are 3" returns).

### Drawing conventions

- Show all dimensions in inches only (never feet).
- Only label a cabinet with a name when the user gives one.
- Default sizes are `DIMS` in `kitchen.js` (cabinet height, toe kick, countertop, depths, aisle, ceiling, the island's counter strips, the cooktop center); the drawing code reads them from there. 1" counter overhang at each end.
- Front sketches (`sketch.js`, `sketch()`): graph paper, 1 square = 6", bold line every 30", measured from the left end of the run and the floor. Upper cabinet codes go in the margin above the ceiling, the top cabinet first; a ruler is on the right. Every sketch has a tape measure (`tape()`, set up by `page()`).
- The top views (`plan(title, run, opts)` in `sketch.js`, `opts.island` for the island): one run each, the wall top under the wall front and the island top under the island front, drawn as if looking down from the aisle: cabinet backs at the top, fronts facing down, left to right as in the front sketch, out to the middle of the 48" aisle (between the door and drawer faces, 3/4" in front of the 24" boxes, `FRONT`). Depths are measured from the cabinet backs (the wall, for the wall run). The wall top shows the room wall, the side wall at Coffee, the dimmers and the Picos; the island top its back wall and stools. Upper cabinets are dotted (`d` deep, else 12"). Countertop appliances are not drawn. `model.html` keeps both runs together, the wall run flipped so its Coffee end lines up with the island's spices end.
- `sketches.html` passes `opts.extra` to each `plan()` for the work areas and lights (a callback `plan()` hands `text` and page-coordinate helpers `x(u)`/`y(v)`). The A lights sit down the middle of the aisle between opposite centers, on both plans. Light groups: T task, A ambient, X accent (toe kick and glass cabinets), UC under-cabinet; each plan has a legend checkbox per group (its twin in the other plan follows), off by default, that hides its marks, arrows and shadows; a `people` checkbox on the island top, also off by default, hides the 74" people and all the shadows (class `l-T` etc.).
- Island positions (faucet, button, sink, cooktop) are measured from the cabinet backs. The counter is 25 3/4" deep (1" past the 3/4" fronts, 2026-11-05) plus a strip past the cabinet backs: 19 1/2" behind spices, cooktop and plates (15" past the back wall; `back: 19.5` on those items), 5 1/2" behind the rest (the `back` argument of `side()` in `sketch.js` and `model.html`). The cooktop is centered 10 1/2" from the cabinet backs and the hood is centered over it (2026-11-05); the sink runs 4"–23" from the backs, 2 3/4" from the counter front.
- Cabinets are listed left to right in `kitchen.js` as `{ name, code, w, kind, note, url, role }`. `kind` is one of `drawers` (with `n`), `door`, `sink`, `base` (drawer over one door), `oven` (the tall OVD3393, with the HBL87M53UC combination oven in it), `gap` (with `tag`, e.g. DW/REF), `panel`, `pantry`, `space` (empty and unlabeled, with `h`). Items with `h` are tall and get no countertop; the counter covers each stretch of base-height items.
- Other item fields: `upper: [ { code, h, at, glass, one, left, w, dx, d } | { appliance, w, h, at, dx, off } | { coffee: true, w, h, at, off } | { light, w, h, at, inside } | { hood: true, w, h, at, chimney } | { pendant: true, w, h, at, dx } | { riser: true, h, at, w, dx, d, side } ]`; `inside: [{ label, w, h, at, dx, within }]` for things hidden in a cabinet, drawn dashed (center `at` off the floor, `dx` from the item's left end); `cooktop`, `falseTop`, `dishwasher`, `fridge`, `bowl`, `faucet`, `airSwitch`, `receptacle`, `receptacleAt` (its center off the floor, else 44"), `backReceptacle`, `back`, and `drop: n` (moves labels n rows down). `one: true` draws a wall cabinet or `door` item with one hinged door, its pull on the right (`left: true` on a wall cabinet puts it on the left). `off: true` starts an appliance hidden.
- `sketch()` options on the wall front: `toggles` (appliance checkboxes), `walls` (the side wall at Coffee: drops the counter's end overhangs, moves the ruler right).
- Page colors are the `var(--name)` tokens: `theme-light.css` holds the light set (the sketches on screen, every page in print, for the trades) and `theme.css` imports it and overrides it with the dark set under `@media screen`. Never hard-code them in a page. Material colors in drawings stay literal. A drawing label on the sheet uses the default text color; one on a light material gets class `on` (dark text, white halo), which also holds on the dark fabrication map in `countertop.html`.
- Colors: Colonial Maple Alabaster #ebeae6 on the upper cabinets, pantry, OVD3393, REP panels and skin (`.alabaster`, `M.alabaster`); Haze #bec6bd on everything else (`.box`/`.front`, `M.box`/`M.front`/`M.base`). All pulls are black, 8" long (`M.pull` in the model); the sketches draw them orange (`.pull`, 2026-11-05) so they stand out, and the oven's handles stay black (`.handle`). The door's recessed panels are not drawn.

### The runs

- The island (spices to cabinet a) and the wall run (FP2496 skin to Coffee, then the side wall) are `RUNS` in `kitchen.js`; their sizes, codes and notes are there and in `cabinets.html`. Read them there rather than keeping a copy here.
- Not in the runs: the island's 4 1/2" back wall (2x4 studs, 1/2" drywall both sides, cabinet height) runs the full length with six receptacles facing away from the aisle, and the cooktop junction box and trash cabinet receptacle open into those cabinets; no riser. Three counter stools (`DIMS.stools`) sit behind spices, cooktop and plates.
